# Propagation Plan: morel-java to morel-rust.1

This document maps disabled test regions in morel-rust.1 to the
morel-java (morel.3) commits that introduced the corresponding
feature. The goal is to enable all disabled regions by applying
morel-java commits in order.

**Baseline**: morel-rust.1 HEAD
`a4b439b683f80bf75f0d81fdfec99d8b142eb8d7` (2026-04-04)

Generated by: `python3 scripts/analyze_disabled.py`

A region is **disabled** if it is inside a `(* ... *)` block
comment OR preceded by `set("mode","validate")` with no intervening
`set("mode","evaluate")`. Table B shows only regions whose
corresponding content is in *evaluate* mode in morel-java; regions
disabled in both repos are excluded.

## How to proceed

### Picking the next commit

Find the earliest row in Table A (lowest C-number / oldest date)
whose commit still has at least one corresponding row in Table B.
That is the next morel-java commit to propagate.

### Implementing the feature

Read the rows in Table B that reference the chosen commit. They
describe which `.smli` regions need to be enabled and therefore
which feature must be implemented in Rust. Use the morel-java
commit itself as the primary specification:

```
git -C /Users/jhyde/dev/morel.3 show SHA
```

Implement the feature, then enable the disabled regions by either
removing the surrounding `(* ... *)` comment delimiters or
replacing `set("mode","validate")` / `set("mode","evaluate")`
brackets with ordinary enabled code.

### Verifying

Run `/usr/local/bin/fullMake` and confirm it passes before
committing.

### Commit message

Use the original morel-java commit summary as the first line of
the commit message. Append a blank line and then a propagation
line that cites the morel-java issue and commit SHA:

```
Join (hydromatic/morel#72)

Add clauses to `from` to support inner joins. We continue to
allow comma joins, but only up until the first step (`where`,
`join`, `group`, `yield` or `order` keyword). After that,
commas would introduce ambiguity when combined with the
commas in `group` or `compute`.

We will add outer joins (`left`, `right`, `full` keywords)
in a later commit.

Propagates hydromatic/morel#72 commit ab102172
```

If a morel-java commit uses old `[MOREL-NNN]` format, convert
it to the new format `hydromatic/morel#NNN`. For example,
`[MOREL-72] Join` becomes `Join (hydromatic/morel#72)`.

### Keeping the plan current

After enabling regions or after any other commit that edits
`.smli` files, re-run the script to regenerate this file:

```
python3 scripts/analyze_disabled.py > /tmp/plan_body.txt
# then prepend the header section and overwrite plan.md
```

The script always reflects the *current* state of the files, so
re-running it automatically removes rows that have been enabled
and updates line numbers that have shifted.

### Stale line numbers

When commits are added to this branch (e.g., cherry-picks from
`0032-propagate`, or intermediate fixes) they may edit `.smli`
files and shift line numbers. The line numbers in Table B are
valid only at the baseline commit shown in the header.

To find where a stale region sits in the *current* file, use
`git diff` between the baseline and HEAD for that file:

```
git diff a4b439b6 HEAD -- tests/script/relational.smli
```

Count how many lines were inserted or deleted before the region
to compute the offset, or simply re-run the script (preferred).
